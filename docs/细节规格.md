# 坐姿监测 · 细节规格：角度测量与提醒引擎

本文档把两个最容易做砸的模块抠透：**指标怎么算才对**、**提醒怎么设计才不烦人**。

---

## 一、坐标系与角度测量

### 1.1 坐标系约定（先定死，后面全按这个来）

- **图像像素系**：原点左上，x 向右，**y 向下**（图像惯例，与数学坐标系相反——这是角度算错的头号来源）。
- MediaPipe 返回的 `landmark.x/y/z ∈ [0,1]` 归一化坐标，**必须先乘回像素宽高**再算角度：
  `px = x * W, py = y * H`。直接拿归一化坐标算角度，非 4:3 画幅下全部失真。
- z 是以髋部中点为原点的相对深度（**人越靠近摄像头 z 越负**），单位与 x/y 一致。不可跨人、跨 session 比较，但同一次坐姿内可用于测前后移动。
- 参考竖直方向 = 图像 y 轴方向 `(0, +1)`。

### 1.2 关键点选取

| 符号 | MediaPipe 索引 | 说明 |
|---|---|---|
| ear_l / ear_r | 7 / 8 | 左右耳 |
| sh_l / sh_r | 11 / 12 | 左右肩 |
| nose | 0 | 鼻 |
| hip_l / hip_r | 23 / 24 | 左右髋（久坐/起身检测） |
| ear_mid | (7+8)/2 | 耳中点 |
| sh_mid | (11+12)/2 | 肩中点 |

### 1.3 指标定义（M1 先做指标 1，其余 M2）

**① 颈线偏角 θ（主指标）**

```
v = ear_mid − sh_mid          # 颈向量，从肩指向耳（图像系 y 向下，故 v.y < 0）
θ = math.atan2(v.x, −v.y)     # 相对竖直向上方向的偏角，单位度
```

判读：
- θ ≈ 0°~15°：正常（人不会完全笔直，别定 0° 为理想值）
- |θ| > 25°：警告；|θ| > 40°：严重
- θ 的正负表示头偏向图像哪一侧：记录方向，判级用绝对值
- 注意：正面相机下 θ 主要反映**侧向偏移 / 颈线斜率**；矢状面"头前移"2D 测不准，用 ②b 颈长比 + z 辅助（见 1.4-5）

**② 低头指标（正面相机主指标）**

侧视图里"鼻-耳连线与水平的夹角"只在侧面相机成立：正面相机下鼻与耳中点几乎同 x，`atan2(q.y, |q.x|)` 会退化到 ±90°。正面正确做法：

```
d = (nose.y − ear_mid.y) / scale    # 鼻相对耳中点的垂直下移量；scale = 肩宽（像素）
```

- d > 0 表示鼻低于耳（低头）；d 起步阈值 0.35，出线 0.28（M2 用实测数据校准）
- **②b 颈长比 r**（前移/含胸代理）：`r = |ear_mid − sh_mid| / scale`，正面相机下头前移会让耳-肩距离缩短，r 变小 ≈ 含胸；相对个人基线判级（M3 自适应）
- **②c 俯仰角 φ**（实验性，依赖 z）：`φ = math.atan2(q.y, |q.z|)`，q = nose − ear_mid；正值 = 低头，z 噪声大时返回 None，只作辅助（M3）

**③ 双肩水平差 s**

```
s = |sh_l.y − sh_r.y| / |sh_l.x − sh_r.x|   # 归一化斜率
```

- s > 0.15 判高低肩/歪坐。**此指标在正面视角下最稳**，优先级可以放高。

**④ 久坐时长**

- 状态"在座"：髋关键点可见度 > 0.5 且髋中点 y 在历史均值 ±15% 内。
- 离座（起身/离开）：髋 y 突变 > 15% 或关键点消失 > 10s → 计时器清零。
- 累计在座 > 45 min 触发久坐提醒。

### 1.4 必须处理的坑

1. **丢帧/遮挡**：`visibility < 0.5` 的关键点不参与计算；关键点缺失时状态显示"未检测"，**绝不进入坏姿势计数**（否则你去接杯水回来就被提醒轰炸）。
2. **抖动**：每个指标先过 **5 帧滑动中值滤波**（抗单帧野值），再进状态判定。不要用均值——野值会拉偏均值，中值不会。
3. **转头失真**：头左右转动时，耳-肩距离在图像里被"压扁"，θ 会虚大。检测方法：`|ear_l 到 sh_l 的距离 − ear_r 到 sh_r 的距离|` 差异大 = 侧脸，此时 θ 不可信，只信 φ 和 s。**这是正面摄像头方案的固有局限，答辩时要主动讲。**
4. **坐姿变化**：趴桌、后仰、盘腿都会让髋/肩几何变化。方案：阈值默认值 + M3 阶段用个人历史分布自适应校准（比如取自己两周数据里 θ 的 85 分位数作为警告线）。
5. **正面摄像头的根本局限**：真正的"头前移"（ear 相对肩沿前后方向平移）在正面 2D 投影里测不准，只能用 z 做粗略辅助（`ear_mid.z − sh_mid.z` 持续变负 ≈ 头靠近摄像头）。**M1 不做 z 融合**，先把 φ + θ + s 做扎实；z 融合是 M3 的进阶项，也是答辩里"改进方向"的现成素材。

## 二、提醒引擎（状态机 + 迟滞）

设计目标：**该提醒时一定提醒，不该提醒时一次都不响**。所有时间参数进 `config.py`，可调。

### 2.1 状态机

状态：`NORMAL`（姿势正常）→ `COUNTDOWN`（坏姿势计时中）→ `ALERTED`（已提醒）→ `SNOOZED`（用户主动小睡）→ 回 `NORMAL`

转移规则：
- `NORMAL → COUNTDOWN`：滤波后指标越线（θ>25° 或 φ>阈值 或 s>0.15），开始计时。
- `COUNTDOWN → NORMAL`：指标回线**且连续保持 3s**（迟滞，防抖动来回横跳）。
- `COUNTDOWN → ALERTED`：坏姿势**连续持续 ≥ 15s** → 触发一次提醒（托盘变红 + 气泡/短音）。
- `ALERTED → NORMAL`：指标回线并连续保持 5s。
- `ALERTED` 自循环（冷却）：仍坏 → **每 300s 最多再提醒一次**，绝不逐帧提醒。
- `ALERTED → SNOOZED`：用户点"小睡 30 分钟"→ 30 min 内静默，期间只记录不提醒；到点回 `NORMAL` 重新计数。
- 升级：同一次坏姿势持续 > 10 min → 提醒升级为"严重"级别（文案不同、声音不同）。

### 2.2 防疲劳三件套（缺一个都会被你关掉）

1. **迟滞**：进警告线和出警告线不共用一条线。进 25° / 出 18°，防止在临界值附近疯狂触发。
2. **冷却**：触发后 300s 内最多一次提醒（用户可改 120~600s）。
3. **静默与上限**：23:00–08:00 静默；每日提醒上限 20 次，超限只变图标不弹窗。

### 2.3 提醒文案分级

| 触发 | 文案示例 |
|---|---|
| 姿势类（15s） | "头前倾 28°，持续 1 分钟了，抬抬头" |
| 久坐类（45min） | "坐了 45 分钟，起来走 2 分钟" |
| 严重（10min+） | "已经连续低头 12 分钟，建议先停下休息" |

原则：**文案带具体数字**（角度/时长），比"请注意坐姿"有效得多，答辩里也是"人机交互设计"的加分点。

### 2.4 状态置信度门槛

- 只有 `visibility ≥ 0.7` 的帧才进入状态机投票；低于 0.7 计为"未知"，**冻结计时器**（不累计坏时间，也不清零，保持原状态）。
- 这一条能消掉 80% 的"莫名其妙被提醒"。

## 三、`posture_rules.py` 接口草图

```python
# 输入：MediaPipe 关键点列表（已换算到像素坐标）+ 上一帧状态
# 输出：指标 dict + 建议状态；纯函数，可单测、可回放录制数据

@dataclass
class Metrics:
    theta: float | None      # 头前倾角（度），None = 置信度不足
    phi: float | None        # 头下垂角（度）
    shoulder_tilt: float | None
    sitting_seconds: float
    confidence: float        # 本帧综合置信度

@dataclass
class PostureState:
    level: str               # "good" | "warn" | "bad" | "unknown"
    reasons: list[str]       # 越线项，如 ["theta=28.3>25", "phi=41>35"]

def analyze(keypoints, prev: dict, cfg) -> tuple[Metrics, PostureState]: ...
```

`ReminderEngine` 单独一个类，只吃 `PostureState`，负责状态机与"何时发声"——**判定与提醒分离**，两个模块各自可测。
